# ПОС — Преподавательская оценка студентов

**ПОС** — консольное приложение для учёта студентов, критериев оценивания и выставленных оценок. Программа рассчитывает итоговый результат по весам критериев, сохраняет данные в JSON и экспортирует ведомость в CSV.

Проект реализован на **Python** с использованием **Domain-Driven Design (DDD)**, архитектуры **Ports & Adapters (Hexagonal Architecture)**, Dependency Injection и паттернов GoF.

## 1. Возможности

- Добавить студента, посмотреть список, изменить имя и удалить студента без выставленных оценок.
- Добавить критерий оценивания с названием, максимальным баллом и весом; посмотреть рубрикатор.
- Выставить, посмотреть, исправить или отменить оценку студента по критерию.
- Рассчитать итоговую оценку по весам критериев в процентах.
- Сохранить студентов, рубрикатор и оценки между запусками в JSON.
- Выгрузить итоговые оценки всех студентов в CSV.
- Запускать автоматические тесты доменной логики, сервисов, репозиториев, консоли и экспорта.

Приложение рассчитано на **один курс и один рубрикатор**. Изменение и удаление критериев, несколько курсов, апелляции и пересдачи не реализованы.

## 2. Требования и запуск

Нужен **Python 3.11 или новее**. Для запуска самого приложения сторонние библиотеки не требуются: используются только стандартные модули Python.

Откройте терминал **в корне проекта** (папке, где находятся `pos/` и `tests/`) и выполните:

```bash
python -m pos.main
```

Для Windows, если команда `python` недоступна, можно использовать `py -m pos.main`.

При запуске открывается консольное меню с операциями со студентами, критериями и оценками. Пункт **12** экспортирует результаты в `data/results.csv`, а **0** завершает работу.

### Пример сквозного сценария

1. Выберите **1**, добавьте студента: ID `1`, имя `Иван Иванов`.
2. Выберите **5**, добавьте критерий: ID `1`, название `Домашнее задание`, максимум `10`, вес `2`.
3. Выберите **7**, выставьте студенту `1` по критерию `1` балл `8`.
4. Выберите **11** и укажите ID `1`: итог составит `80.0%`.
5. Выберите **12**, чтобы сохранить ведомость в `data/results.csv`.
6. Завершите работу через **0** и снова запустите программу: студенты, критерии и оценки сохранятся.

**Важно:** пути `data/...` отсчитываются от текущей рабочей папки; рекомендуется запускать приложение из корня проекта. Для добавления студентов или критериев повторно используйте новые ID, иначе сработает защита от дубликатов.

## 4. Предметная область и DDD

### Ubiquitous Language — единый язык

| Термин | Смысл в проекте |
| --- | --- |
| **Student (студент)** | Участник курса, которому выставляют оценки |
| **Criterion (критерий)** | Правило оценивания с названием, максимумом и весом |
| **Rubric (рубрикатор)** | Набор допустимых критериев оценивания |
| **Evaluation (оценка)** | Выставленный конкретному студенту балл по конкретному критерию |
| **Score (балл)** | Числовое значение выставленного балла |
| **Final Score (итог)** | Вычисляемый результат студента, а не отдельно хранимая произвольная цифра |

### Entity и Value Object

**Сущности (Entity):** `Student` и `Criterion` различаются по уникальному `id`. Для `Evaluation` фактическим идентификатором служит пара `(student_id, criterion_id)` — одна актуальная оценка по критерию у студента. При исправлении оценки сохраняется эта пара, но заменяется соответствующий объект.

**Объект-значение (Value Object):** `Score` не имеет ID. Два экземпляра `Score(8)` равны по значению. Публичное свойство `value` доступно только для чтения; проверка конструктора запрещает отрицательные числа, `NaN` и бесконечность.

### Агрегат и инварианты

`Rubric` выступает **корнем агрегата рубрикатора**: критерии добавляются через метод `add_criterion()`, а попытка повторно использовать ID критерия отклоняется.

Основные правила предметной области:

- ID студента и критерия должны быть положительными.
- Имя студента и название критерия не могут быть пустыми.
- Максимум и вес критерия должны быть положительными конечными числами.
- `Score` не может быть отрицательным, бесконечным или `NaN`.
- Выставляемый балл не превышает максимум критерия.
- Выставить оценку можно только по критерию из действующего рубрикатора.
- Повторная оценка по той же паре «студент — критерий» добавлением запрещена: для исправления служит отдельная операция.
- При попытке удалить студента с оценками приложение сообщает об ошибке.
- Итог каждый раз вычисляется по текущим оценкам и рубрикатору, не хранится как отдельное редактируемое поле.

Для нарушений правил используется исключение `DomainError`. Проверки сосредоточены в доменной модели, фабрике и соответствующих сценариях приложения, а не в консольном меню.

Ключевые поля моделей доступны через `@property` без публичных сеттеров. Это защищает от случайного изменения через обычные присваивания вроде `criterion.max_score = -1`; внутренние атрибуты Python с `_` при этом не являются абсолютной защитой от намеренного вмешательства.

### Domain Service и расчёт итога

`FinalScoreCalculator` реализует правило, которое зависит сразу от рубрикатора и нескольких оценок, поэтому вынесено в **Domain Service**.

Формула итоговой оценки:

```text
final_score = 100 * SUM((score_i / max_score_i) * weight_i) / SUM(weight_i)
```

По умолчанию действует `MissingAsZeroStrategy`: **невыставленная оценка учитывается как 0**, а вес её критерия остаётся в знаменателе. Если в рубрикаторе нет критериев, возвращается `0.0`. Результат округляется до двух знаков после запятой.

Пример: домашнее задание — `8/10` с весом `2`, семинары — `5/5` с весом `1`:

```text
100 * ((8/10)*2 + (5/5)*1) / (2+1) = 86.67%
```

Вторая реализованная стратегия, `GradedOnlyStrategy`, считает предварительный процент **только по оценённым критериям**. Она используется в тестах и доступна для подстановки в `FinalScoreCalculator`; в обычном консольном меню применяется `MissingAsZeroStrategy`.

## 5. Архитектура Ports & Adapters

Выбрана облегчённая **Hexagonal Architecture (Ports & Adapters)** с разделением ответственности по слоям:

- **Domain** (`pos/domain`) содержит модели, инварианты, фабрику, доменный сервис, стратегии и интерфейсы репозиториев. Он не импортирует консоль, JSON или CSV.
- **Application** (`pos/application`) реализует сценарии работы с оценками, фасад для UI и порт экспорта. Зависит от доменных объектов и абстракций, но не от конкретных адаптеров хранения.
- **Infrastructure** (`pos/infrastructure`) предоставляет InMemory- и JSON-репозитории, экспорт CSV и контейнер сборки зависимостей.
- **Presentation** (`pos/result/cli.py`) читает пользовательский ввод, вызывает фасад и показывает сообщения.

Схема взаимодействия при выставлении оценки:

```text
ConsoleUI (ввод команды)
    |
    v
PosFacade (единая точка входа)
    |
    v
EvaluationService (сценарий приложения)
    |                  |
    v                  v
EvaluationFactory   Repository ports
    |                  ^
    v                  |
Domain model        JSON / InMemory adapters
```

Инфраструктурные адаптеры реализуют внутренние порты, а не наоборот. Исключение по роли — `Container`, находящийся на **composition root**: он знает о конкретных адаптерах, создаёт их и передаёт сервисам и фасаду через конструкторы.

## 6. Паттерны GoF

| Группа | Паттерн | Где применяется | Какую задачу решает |
| --- | --- | --- | --- |
| Порождающий | **Factory** | `EvaluationFactory` (`domain/factories.py`) | Централизует создание `Score` и `Evaluation`, используя проверки доменной модели и рубрикатора |
| Структурный | **Facade** | `PosFacade` (`application/facade.py`) | Даёт консоли единый набор операций для студентов, критериев, оценок, итогов и экспорта; скрывает координацию компонентов |
| Поведенческий | **Strategy** | `MissingAsZeroStrategy`, `GradedOnlyStrategy` (`domain/services.py`) | Позволяет выбирать правила учёта невыставленных оценок без изменения алгоритма подсчёта |

Применено **по одному паттерну из каждой группы**, чтобы показать реальную пользу, а не увеличивать число классов ради шаблонов проектирования.

## 7. Repository и Dependency Injection

Порты хранения объявлены в `pos/domain/repositories.py`:

- `StudentRepository` — добавление, поиск, список, обновление, удаление студента;
- `RubricRepository` — получение и сохранение одного рубрикатора;
- `EvaluationRepository` — добавление, поиск, список, исправление и удаление оценок.

Каждому порту соответствует реализация для хранения в памяти и для JSON. `EvaluationService` получает зависимости **через конструктор**, а не создаёт конкретные репозитории самостоятельно.

`Container` (`pos/infrastructure/container.py`) связывает зависимости:

- `Container()` создаёт независимые **InMemory**-репозитории (удобно для тестов).
- `Container(data_dir="data")` создаёт **JSON**-репозитории (используется при обычном запуске).

Таким образом, тип хранения выбирается в одном месте без изменения доменной логики.

## 8. Форматы хранения и экспорта

Приложение сохраняет данные в папке `data/`:

| Файл | Содержимое |
| --- | --- |
| `students.json` | Список объектов `{ "id", "name" }` |
| `rubric.json` | Список объектов `{ "id", "name", "max_score", "weight" }` |
| `evaluations.json` | Список объектов `{ "student_id", "criterion_id", "score" }` |
| `results.csv` | Итоговая ведомость всех студентов |

При чтении JSON данные преобразуются обратно в объекты доменной модели, поэтому снова выполняются проверки конструкторов. CSV создаётся модулем `CsvExporter` через `ExportPort` и использует кодировку **UTF-8 с BOM** (`utf-8-sig`) и разделитель `;` для удобного открытия в Excel.

Пример содержимого `results.csv`:

```csv
student_id;student_name;final_score
1;Иван Иванов;86.67
2;Мария Петрова;0.0
```

**Особенности текущей реализации:** JSON-файлы рассчитаны на запись самим приложением. Полная валидация структуры вручную изменённых файлов и атомарная запись при возможном сбое пока не реализованы; их рекомендуется добавить перед окончательной сдачей.

## 11. Ограничения и возможное развитие

- Один рубрикатор для одного курса, без поддержки нескольких курсов.
- Одна текущая оценка на пару «студент — критерий»; история исправлений, комментарии и даты не хранятся.
- Критерии можно добавлять и просматривать, но нельзя изменять или удалять через меню (по условию ДЗ это необязательно).
- При удалении студента с оценками операция отклоняется, чтобы не создавать «осиротевшие» оценки.
- Дополнительные возможности на будущее: импорт ведомостей, история оценок, апелляции, более строгая проверка JSON, атомарное сохранение и дополнительные стратегии итогового балла.
